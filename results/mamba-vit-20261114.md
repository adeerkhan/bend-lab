# MambaViT on this lane — reference, twin, and the flower runs (2026-11-14)

Reference: JLrumberger/MambaViT `0236b08`. A ViT (patch embed, cls token,
learned pos embedding, mean/cls pool, linear head) whose blocks are
**Mamba-1** (`mamba_ssm.Mamba` via `create_block`). Its own code cannot run
here: `mamba_ssm` (Mamba-1) and `causal_conv1d` are not installed and not
vendored. `reference/mamba_vit_twin.py` reimplements the same model in plain
torch (with `mamba_ssm`'s shapes, math and initialisation), and is the
oracle for the port.

## The twin reconstructs the reference's claim

| run | config | params | result |
|---|---|---:|---|
| reference README's claim | MNIST, 28×28, patch 4, dim 32, 8 layers, mean pool | — | ~90 % val "in a couple of epochs" |
| twin, 1 epoch, batch 64, AdamW 1e-3 / wd 0.01 / clip 1.0, RTX 5060 | same | **83,050** | **val 94.61 %**, train 67.98 %, 4 m 05 s |

Command: `reference/.venv-rf/bin/python reference/mamba_vit_twin.py --epochs 1`.
So the twin is a valid stand-in and already matches/beats the reference's
published MNIST behaviour.

## Flowers: MambaViT is a classifier, not a generator

MambaViT produces class logits, not images. The flower **image** results in
this lab come from the flow-matching UNet, not MambaViT: held-out legibility
`0.490093` against the twin's `0.489027`, ceiling `0.5621`, final loss
`0.289049` (`results/RESULTS.md`, task `flowers-flow`).

Classification runs of the twin on flowers (same machine, this session):

| data | config | params | result |
|---|---|---:|---|
| Oxford Flowers-102, pinned cache (`~/.cache/bend-lab/flowers`), 2048 train images, 2 epochs | 64×64 RGB, patch 8, dim 32, 8 layers | 92,550 | held-out **1.18 %** (chance 0.98 %) — no signal at this budget |
| 5-class folder set (`/tmp/opencode/flowers/flower_photos`), 1500 images, 80/20 split, 3 epochs | same | 89,349 | held-out **34.0 %** (chance 20 %) — learns, 16 s of training |

Commands: both were run with `reference/.venv-rf/bin/python` against
`reference/mamba_vit_twin.py`'s `MambaViT` class (see this session's shell
history; the 5-class set is another session's temporary copy and is not
pinned — the Oxford-102 cache is the reproducible source).

## What this means

- The architecture is reproduced and its MNIST claim holds.
- On flowers, a 1-epoch-scale tiny MambaViT learns something only on the
  coarse 5-class task; fine-grained 102-class classification needs a real
  schedule, more data and likely a larger `dim`/`n_layer` — do not read an
  architecture verdict from the 1.18 % run.
- MambaViT cannot be compared to the lab's flower image quality: it has no
  decoder. The image comparison stays the UNet's.
